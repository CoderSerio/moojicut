# 选区几何

本包只计算数值几何：拖拽矩形、八个手柄的位置与命中、边框命中、移动和缩放。
它不持有手势会话、窗口或文档。宿主继续维护开始、预览、完成和取消状态，
并负责事件坐标转换、指针夹取、像素取整、绘制和文档提交。

矩形使用 `[x, y, width, height]`，手柄自左上角开始顺时针编号 `0..7`。
移动保留宽高；Linux 箭头的宽高可以为负，不能在移动时改成无方向的矩形。
`region` 和 `contains` 会按需要规范化边界，`transform` 保留有向尺寸。

## 以 macOS 为共同基准

三端采用现有 macOS 选区的移动、缩放和命中规则，不再按平台选择几何策略。
当最小尺寸大于可用范围、夹取区间出现 `low > high` 时，也保持 macOS 的运算顺序：

| 操作 | 夹取规则 |
| --- | --- |
| 移动、右边、下边 | `max(low, min(value, high))` |
| 左边、上边 | `min(high, max(low, value))` |

`transform` 默认 `directed=false`，移动时完全保留 macOS 的原始矩形算法，
包括传入负宽高时的数值结果。只有显式传入 `directed=true`，移动边界才按有向宽高
扩展，让箭头的两个端点都在可用范围内；宽高为正时两种表示的移动结果相同。
这是矩形与有向端点的表示适配，不是平台策略，且不改变缩放规则。

最小尺寸由宿主按对象用途传入，例如选区 `2px`、标注 `8px`。
缩放不会因越过对边而翻转，也不在这里再次夹取指针；每次使用原始矩形及
指针相对手势起点的总位移。

`midpoint_mode=0` 保留精确中点；`1` 对最终中点坐标朝零截断，与 Windows 整数坐标一致。
不能先截断半个宽度再加原点，否则奇数尺寸、负坐标的结果会不同。
所有手柄命中区均包含左、上边，排除右、下边，与 AppKit 一致。
重叠命中区始终返回编号最小的手柄。边框使用同样排除最大边的矩形判断，
缩进后宽高非正的内矩形不参与扣除。有向标注的 `contains` 独立保留包含端点的语义，
不用于判断手柄命中区。

根包 `api_selection.mbt` 保留薄 C 接口。返回的 `FixedArray[Double]` 由调用方持有，
读取坐标后须调用 `moonbit_decref`；核心不保存返回数组或其他调用状态。
`selection_transform` 的末尾参数 `directed` 为整数，`0` 使用默认矩形表示，
非零值启用有向端点边界。
白盒测试覆盖 macOS 基准的命中与缩放边界、反向拖动、八方向缩放、非零边界、
有向箭头、负宽高的表示区别、中点取整和不同用途的最小尺寸。
